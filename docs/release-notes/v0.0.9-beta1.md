## holzBar 0.0.9 beta 1

The first beta of 0.0.9. It adds **widgets**: small items of your own in the menu bar, such as a clock, the battery, the CPU load, a Shortcut button or the first line of a script's output. holzBar hides, reveals, orders and remembers them like any other item. **Like the earlier betas, the new feature is a Preview: built and unit tested, but not yet tested on a real Mac by the maintainer.** It carries a **Preview** badge in the app. Please try it and report what does not work on the [issue tracker](https://github.com/holzcloud/holzBar/issues).

### ✨ Highlights
- **Widgets** (Preview), an optional module in **Settings → Menu Bar Layout**. It is off until you switch it on and costs nothing while it is off. At most six widgets, on macOS 14 to 27.
- **Seven sources, none needs a permission**: date and time, battery (percent, with or without the charging state), CPU load, memory (percent or gigabytes used), uptime, free disk space and a countdown to a moment you pick. Formats are presets written in your language and region, with an optional symbol.
- **A Shortcut button** shows a title or a symbol and runs a Shortcut you choose by name, through the Shortcuts app. holzBar shows nothing of its own, and the Shortcuts app is not brought to the front.
- **A script widget** shows the first line of the output of a script you allowed in Automation, Scripts, as plain text in a narrow, medium or wide fixed width. It never runs on a timer and never while hidden, and has its own limit of one run per 30 seconds per widget and ten a minute.

### ✨ New
- **Fixed widths.** A widget keeps one width for its format, so its text never moves the items beside it. A value that cannot be read shows an en dash, and VoiceOver says "unavailable".
- **Light on energy.** A widget refreshes only while it is visible, never while it is hidden, or while the Mac is asleep or locked, and refreshes once when it is shown again. The battery comes from power events, not from a timer. Low Power Mode doubles the polling intervals. Seconds exist for the clock only, and the pane says what they cost.
- **Part of the bar like any item.** Widgets can be moved between sections, are kept in layout profiles, appear under their own names in the layout editor, the search, groups, hints and the holzBar Shelf, and a Shortcut button runs from the Shelf and the search too. A new widget starts in the visible section.
- **macOS 27.** holzBar hides a widget itself by collapsing it, under its own key in the saved layout, so holzBar's own icon is never concealed.
- **Export and sharing.** Your settings export carries widgets without Shortcut names and without scripts, so an imported button says "Choose a Shortcut" and an imported script widget says "Choose a script". Shared profiles never carry a widget.
- **VoiceOver.** Each widget has a label and a value, and the list has Move Up and Move Down actions.
- New texts exist in English, German, French, Italian and Romansh; the French, Italian and Romansh texts are machine-made and not yet checked by a native speaker.

### 🔒 Security
- Widgets add no permission and no network access. A script widget runs only a script you allowed first, under every rule of Scripts, and is told `HOLZBAR_EVENT=widget-refresh` and nothing else. A URL command or a Shortcut that reveals a hidden section makes a script widget visible, which runs its already allowed script once; it cannot bind, allow or choose a script.
- Which script a widget runs is kept on this Mac only: it is never exported, imported or shared.

### ⚠️ Known issues
- **Nothing in this beta was tested on a real Mac by the maintainer.** The macOS 27 collapse, the macOS 26 recognition of a widget's window, the position of a widget after a relaunch and the energy cost are unverified.
- A script widget refreshes when it appears and on a click, and on system events only while an enabled automation rule follows that kind of event.
- On macOS 27 "Show When It Changes" does nothing for a widget.
- The AppleScript dictionary, animations, more triggers (Bluetooth, audio, Energy Mode) and settings sync are planned for later releases.
- The other known issues of 0.0.8 still apply.

### 📦 Install
Update an installed holzBar (this is a beta; Homebrew installs the newest version of the cask):
```sh
brew update && brew upgrade --cask holzbar
```

New install (quit the original Ice, Thaw, Bartender or Hidden Bar first if one of them is running):
```sh
brew tap holzcloud/holzbar https://github.com/holzcloud/holzBar
brew trust --cask holzcloud/holzbar/holzbar
brew install --cask holzbar
```

If macOS says holzBar can't be opened, take it out of quarantine and open it again:
```sh
xattr -dr com.apple.quarantine /Applications/holzBar.app
```

This release is signed with the same certificate as 0.0.6 and 0.0.7, so updating keeps the Accessibility and Screen Recording permissions.

holzBar runs on macOS 14 Sonoma and later, up to macOS 27. Only macOS 26 and 27 are tested.
