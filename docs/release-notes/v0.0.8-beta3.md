## holzBar 0.0.8 beta 3

The third beta of 0.0.8 "Automation". It finishes scripts, which came in the first betas before they had a security review: after the review, scripts run from a folder of your choice, with their data kept only on this Mac, and a profile can run scripts before and after it is applied. **Like the earlier betas, the new features are Previews: built and unit tested, but not yet tested on a real Mac by the maintainer.** Each one carries a **Preview** badge in the app. Please try them and report what does not work on the [issue tracker](https://github.com/holzcloud/holzBar/issues). Everything else of [beta 2](v0.0.8-beta2.md) is unchanged.

### ✨ Highlights
- **A folder of your choice for scripts** (Preview), in **Settings → Automation → Scripts**. holzBar asks before it switches folders, because every approval is removed and each script in the new folder needs your approval again.
- **Profile hooks** (Preview): a script that runs before or after a profile is applied, for one profile or for every profile. Before hooks run first and holzBar waits for them, each at most its time limit, then applies the profile whatever their outcome; after hooks start once the items have moved and are not waited for. A profile applied by a URL command, a Shortcut or the Focus filter runs no hooks.
- **A script can run when its rule ends** (Preview): in the rule editor, "Also run it when the rule stops being true". It is off for new script rules, and the script knows which of the two it is in `HOLZBAR_EVENT` (`rule-started` or `rule-ended`).
- **The last result and the first line of a script's output** (Preview) are shown in the pane as plain text, one line, at most 80 characters.
- **A time limit per script**, 10 seconds by default and 1 to 60 seconds in the pane.

### 🔒 Security
- **Scripts are not settings.** The rules that use a script, the folder, the approvals, the time limits and the profile hooks live only in `Scripts.json` on this Mac, in a file only you can read. They are never exported, imported or synced, an import neither brings nor removes such a rule, and the import question says how many rules of the file it left out.
- **Nothing from outside runs a script.** A URL command or a Shortcut can turn a rule that uses a script off, never on; turning it off runs no end script; the pass that a change from outside causes asks no script condition and starts no script; and a profile they apply runs no hooks. The price is that a Shortcut cannot switch a scripted rule on.
- **Each check reads the file once, without following links**, and the approval binds the whole SHA-256 checksum, not its first characters. A changed file needs a new approval.
- **Names with hidden characters are refused**, and every name is cleaned and shortened where holzBar shows it.
- **An unsafe folder runs nothing**: a link, a folder that is not yours or one that others can write to.
- **A script that runs too long is stopped together with what it started** (its process group), its output is read to the end up to 64 KB and the rest is dropped, and at most ten runs happen a minute.
- **CI proves that only the script runner and the permission reset start a process**, and `SECURITY.md` gives each threat of the scripts feature its final status, the test or check that proves it and the risks that remain.

### 🔧 Changed
- **The approval is a sheet** that names the file, its folder, its size and the start of its checksum, in fixed wording. **Return cancels**; allowing a script takes a click on the other button.
- **Your scripts from beta 1 and beta 2 move once.** The first time this beta starts, holzBar moves their rules and approvals into `Scripts.json`. The old approvals file stays where it is and is not read again. Rules that run a script keep running it only when they start, as before.
- **A rule whose only condition is a script is asked when power, network, running apps, displays or the wake from sleep change**, and by **Check Now**, at most every 30 seconds per script. There is still no timer of its own.
- The Scripts and Profile Hooks sections carry the **Preview** badge, as do the script rows of the rule editor.
- New texts exist in English, German, French, Italian and Romansh; the French, Italian and Romansh texts are machine-made and not yet checked by a native speaker.

### ⚠️ Known issues
- **Nothing in 0.0.8 was tested on a real Mac by the maintainer.** The Focus filter in particular depends on macOS calling it, which has been reported not to work on macOS 26.5.
- **Scripts run as you, with holzBar's permissions.** macOS asks separately before a script controls another app. Whether an allowed script can use holzBar's own Accessibility and Screen Recording grants has **not been measured on a Mac yet**; until it is, treat an allowed script as being as powerful as holzBar.
- Malware that already runs as you can write a script and its approval too; the checks cannot stop that.
- A before hook cannot cancel a profile: holzBar waits for each before hook at most its time limit and then applies the profile whatever happened, so a broken or missing script never blocks your layout.
- Undoing the deletion of a profile brings the profile back without its hooks.
- Going back to beta 2 hides your script rules until you update again; they stay in `Scripts.json`, and the old approvals file is untouched.
- A VPN is seen only when the traffic goes through a tunnel; a VPN that routes only some networks is not.
- On macOS 27 a rule that shows one item moves all items of its app.
- Widgets, the AppleScript dictionary, animations, more triggers (Bluetooth, audio, Energy Mode) and settings sync are planned for later releases.
- The other known issues of beta 2 and 0.0.7 still apply.

### 📦 Install
Update an installed holzBar (this is a beta; Homebrew installs the newest version of the cask):
```sh
brew update && brew upgrade --cask holzbar
```

New install (quit the original Ice, Thaw, Bartender or Hidden Bar first if one of them is running):
```sh
brew tap holzcloud/holzbar https://github.com/holzcloud/holzBar
brew trust --cask holzcloud/holzbar/holzbar
brew install --cask holzbar
```

If macOS says holzBar can't be opened, take it out of quarantine and open it again:
```sh
xattr -dr com.apple.quarantine /Applications/holzBar.app
```

This release is signed with the same certificate as 0.0.6 and 0.0.7, so updating keeps the Accessibility and Screen Recording permissions.

holzBar runs on macOS 14 Sonoma and later, up to macOS 27. Only macOS 26 and 27 are tested.
