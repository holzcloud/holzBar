## holzBar 0.0.7 beta 4

Two fixes for problems found while running beta 3 on macOS 26: the spinner after **Apply** in the menu bar item spacing setting, and menu bar items of other apps that lost their name and made holzBar re-read the menu bar every minute. Everything from the audit is described in the [0.0.7 beta 2 notes](https://github.com/holzcloud/holzBar/releases/tag/v0.0.7-beta2), settings sync and the opaque glass in the [0.0.7 beta 3 notes](https://github.com/holzcloud/holzBar/releases/tag/v0.0.7-beta3), and everything new in 0.0.6 in the [0.0.6 notes](https://github.com/holzcloud/holzBar/releases/tag/v0.0.6).

### 🐛 Fixed
- **The spinner after Apply no longer runs on and on.** Applying the **Menu bar item spacing** asked Control Center and SystemUIServer to quit. Neither of them does on macOS 26, so every Apply waited about 20 seconds, then showed an error alert that often opened behind other windows, and the spinner waited for that alert. holzBar no longer asks these two system processes to quit, and the spinner stops as soon as the apps are relaunched, before any alert appears. The system items (clock, Wi-Fi, battery) take the new spacing at your next login, as the note in the setting says.
- **Items of other apps keep their app again on macOS 26, and holzBar stops re-reading the menu bar every minute.** Since beta 2, an app's item was only matched to its app when no Apple app was still launching. Apple's WebKit helper processes never report that they finished launching, so on a Mac with Safari, Mail or other web content running, 13 items stayed without an app. holzBar then logged an error for each and rebuilt its item list once a minute. An app that has not finished launching 10 seconds after it started is no longer waited for, and a missing app no longer forces a re-read. An Apple app that is really still launching still holds the matching back, so the protection from the audit stays.

### ⚠️ Known issues
- **None of this beta has been checked on a real macOS 26 or 27 system by the maintainer yet.** Both fixes have unit tests, and the app type-checks, but the Apply spinner and the item names still need hands-on testing. Please report anything that looks wrong on the [issue tracker](https://github.com/holzcloud/holzBar/issues).
- **Native support for macOS 27's own overflow button is not part of this beta.** It comes in a later 0.0.7 beta.
- The other known issues of beta 3, beta 2 and 0.0.6 still apply.

### 📦 Install
Update an installed holzBar:
```sh
brew update && brew upgrade --cask holzbar
```

New install (quit the original Ice, Thaw, Bartender or Hidden Bar first if one of them is running):
```sh
brew tap holzcloud/holzbar https://github.com/holzcloud/holzBar
brew trust --cask holzcloud/holzbar/holzbar
brew install --cask holzbar
```

If macOS says holzBar can't be opened, take it out of quarantine and open it again:
```sh
xattr -dr com.apple.quarantine /Applications/holzBar.app
```

Releases before 1.0 are pre-releases. This release is signed with the same certificate as 0.0.6 and the earlier 0.0.7 betas, so updating keeps the Accessibility and Screen Recording permissions. Coming from 0.0.5, follow "Install and update" in the [0.0.6 notes](https://github.com/holzcloud/holzBar/releases/tag/v0.0.6).

holzBar runs on macOS 14 Sonoma and later, up to macOS 27.
