## holzBar 0.0.8

The first stable release of 0.0.8 "Automation": rules that change the menu bar by themselves, scripts, widgets, a history of your layout, a lock for hidden items, more menu bar styles, dragging items in the menu bar without ⌘, rules for single items and the cooperation with macOS 27's own overflow button. It is the sum of the betas 1 to 5, tested by the maintainer on macOS 26 and 27. Coming from 0.0.7, everything below is new. Please report problems on the [issue tracker](https://github.com/holzcloud/holzBar/issues).

### ✨ Highlights
- **Show Only When… from the item itself**: right-click an item in **Menu Bar Layout** (VoiceOver has the same action) and choose **Show Only When…** to make its rule: the item is shown while the conditions hold and hidden in the Hidden or Always-Hidden section while they do not. It is the editor of the Automation rules with the action fixed, so the rule also shows in the Automation pane. An item has one rule; **Edit Rule…** and **Remove Rule** are in the same menu. An item that a rule controls wears a small eye badge, and its tooltip names the rule. Applying a profile no longer moves such an item: the rule wins, and the Profiles section says how many items that are.
- **Automation**: a pane in Settings for rules of the kind "when these things are true, do this". Conditions: power source and battery level, Low Power Mode, an app running or in front, a time of day, a display connected, Wi-Fi, Ethernet, offline, a hotspot or a VPN, the name of the Wi-Fi network (Location Services is asked for only when you add that condition, and only the name is read), a camera or the microphone in use (macOS 14.2 and later, no permission) and a script. Actions: apply a profile, show a section, turn Zen mode on or off, keep the Mac awake, run a script, or show one item only while the condition holds. A rule acts once when it becomes true and can bring the previous state back when it ends. Nothing is observed unless an enabled rule needs it, and nothing polls.
- **Focus filter**: add the holzBar filter to a Focus in System Settings to apply a profile while that Focus is on; the previous profile comes back when it ends.
- **Scripts**: from a folder you choose, and only after you allowed their exact content on a sheet; the content is checked again before every run. No shell and no arguments, a time limit of 10 seconds by default (1 to 60 in the pane), optionally run again when the rule ends, and the first line of the output is shown in the pane.
- **Profile hooks**: a script that runs before or after a profile is applied, for one profile or for every profile. Before hooks run first (at most five) and holzBar waits for them, then applies the profile whatever their outcome; after hooks are not waited for. A profile applied by a URL command, a Shortcut or the Focus filter runs no hooks.
- **Widgets**: small items of your own in the menu bar, an optional module in **Settings → Menu Bar Layout** that is off until you switch it on. At most six, on macOS 14 to 27. Seven sources that need no permission (date and time, battery, CPU load, memory, uptime, free disk space and a countdown), a Shortcut button and a script widget. A widget refreshes only while it is visible and is part of the bar like any item.
- **Layout History**: automatic snapshots of your arrangement, with a preview of what a restore changes and an undo. Local files on this Mac only.
- **Lock hidden items**: Touch ID or your password before hidden items are shown, with a minute of grace, in **Settings → Advanced**. Your own safety rules (low battery, offline, rules, items you chose) do not ask.
- **macOS 27's own overflow button**: while macOS shows its folded items expanded beside the notch, the holzBar Shelf no longer lists them a second time. Whenever holzBar is not sure, the Shelf lists them as before, so no item becomes unreachable. No new permission.
- **Menu bar styles**: **Sections** draws one shape per section the bar shows (macOS 14 to 26); a shape of its own for the Apple logo in the bar's tint, the accent colour, the wallpaper's colour or a colour you choose; outlines in the accent colour or a gradient; vertical gradients, one gradient per shape and the tint strength. Every default looks as before; no new permission.
- **Drag in the menu bar** (macOS 26 and 27): an optional module in **Settings → Menu Bar Layout**, off until you switch it on. While it is on, you move an app's menu bar item by dragging it, without holding ⌘ Command: sideways to reorder it, and on macOS 26 past holzBar's divider into the hidden or always-hidden section. On macOS 27, drop an item on the holzBar icon to hide its app, or drag a hidden app's item elsewhere while it shows to make the app visible again; the order within a section is up to macOS. On macOS 26 every drop is kept like a move in Menu Bar Layout; on macOS 27 only a drop that hides or shows an app is, and a plain reorder is macOS's own.

### 🆕 New
- **Tidy Up assistant**: proposes which items to hide from static facts only (system extras, the app's category, a short list of known helpers). Offered once after the first launch and any time from Menu Bar Layout. You decide item by item, and a snapshot is kept first.
- **Share a profile** as a small validated file (only the apps you leave checked and their sections) and import one after a look.
- **Copy Diagnostics** in About: a report of versions and counts that you read first and copy yourself. No names of items, apps, profiles or networks; nothing is sent. On macOS 27 it names the state of the overflow button.
- **Revoke each permission** from **Settings → Advanced**.
- **Menu Bar Layout, the Shelf and the search work without Screen Recording** and show app icons until you allow it. A window asks once, the first time the Shelf opens, and **Settings → Advanced** allows or revokes Screen Recording at any time.
- **Pinned system items** (macOS 26 and earlier): profiles and restored layouts leave the clock, battery, Wi-Fi, Control Center and sound where they are.
- **URL commands and Shortcuts for rules**: `holzbar://automation/enable/<name>` and `/disable/<name>` ask first; Shortcuts can turn a rule on or off and list the rules that are active. A rule that uses a script can be turned off this way, never on.
- **Two Homebrew channels** from the same tap: `holzbar` (stable) and `holzbar@beta` (the newest alpha, beta or plain release). They install the same app and conflict with each other.
- A **keyboard and VoiceOver checklist** in [`docs/accessibility-checklist.md`](https://github.com/holzcloud/holzBar/blob/main/docs/accessibility-checklist.md).

### 🛠 Fixed
- **The glyphs on the section strips of Menu Bar Layout are readable.** Widgets and the pictures of items were drawn in black, which is unreadable on the strip's dark colour. They are drawn in white on a dark strip and in black on a bright one.
- **Accessibility**: VoiceOver names the rule, condition, script, profile hook, snapshot and widget rows and reads When and Then, Profile Hooks and every sheet title as headings, the Edit buttons as collapsed or expanded and a rule's battery level in percent; Add Rule puts the cursor in the rule's name; Escape closes Tidy Up, Share Profile, Import Profile, Copy Diagnostics and the script confirmations; with Increase Contrast, Settings draws its groups opaque with stronger borders and text; with Reduce Motion, items in Menu Bar Layout no longer slide; the holzBar Shelf shows a focus ring on the item the arrow keys select; gradient colour stops can be chosen, moved and removed with the keyboard and VoiceOver; the search panel, group popovers and group symbols are read by name; the Preview badge is easier to read in light mode.
- A low-battery rule shows the items again when you unplug the charger while the level stays low. Before, the old setting did not notice that the charger had been in.

### 🔧 Changed
- **Menu Bar Layout shows the sections first.** Below the hint come the Visible, Hidden and Always Hidden bars, then Tidy Up, Profiles, Groups, Spacers, Widgets and Drag in the Menu Bar, and **Layout History** last. Layout History is folded away until you open it and keeps the **newest 10 snapshots** by default; choose from 1 to 100 with **Snapshots to keep**. Starred snapshots always stay and are not counted.
- **A new look for Settings**: glass groups on a calm ground and a sidebar in two groups. In **Menu Bar Layout** the Visible, Hidden and Always Hidden sections are drawn as glass cards, with the items on a strip in the menu bar's colour. Drag and drop works as before.
- **"Show hidden items on low battery" and "when the network connection is lost" are rules now.** The first time 0.0.8 starts, holzBar turns the two settings that were on into two rules in the Automation pane and forgets the old setting; the **Show Hidden Items Automatically** section is gone from Advanced.
- The shape kinds Full and Split are called **Single** and **Paired**; stored values are unchanged.
- The script approval is a sheet on which Return cancels.
- New texts exist in English, German, French, Italian and Romansh; the French, Italian and Romansh texts are machine-made and not yet checked by a native speaker.

### 🔒 Security
- **Scripts are not settings.** The rules that use a script, the folder, the approvals, the time limits and the profile hooks live only in `Scripts.json` on this Mac, in a file only you can read. They are never exported, imported or synced.
- **Nothing from outside runs a script.** A URL command or a Shortcut can turn a rule that uses a script off, never on, and a profile they apply runs no hooks.
- **Each check reads the file once, without following links**, and the approval binds the whole SHA-256 checksum. A changed file needs a new approval. Names with hidden characters are refused, and an unsafe folder (a link, a folder that is not yours or one that others can write to) runs nothing.
- **A script that runs too long is stopped together with what it started**; its output is read up to 64 KB and the rest is dropped, and at most ten condition checks and ten other runs happen a minute.
- **Widgets add no permission and no network access.** A script widget runs only a script you allowed first, under every rule of Scripts.
- **CI proves that only the script runner and the permission reset start a process.** [SECURITY.md](https://github.com/holzcloud/holzBar/blob/main/SECURITY.md) gives each threat its status, the test or check that proves it and the risks that remain.
- **Drag in the menu bar watches only the left mouse button**, and only while the module is on; it reads no key and adds no permission beyond Accessibility. While it is off, holzBar does not watch the mouse for it.

### ⚠️ Known issues
- A rule that controls an item moves it only when its condition changes, after a hold of three seconds. If you move such an item by hand, it stays there until the condition changes, and then it goes back to the visible bar, not to the section you had put it in.
- The Focus filter depends on macOS calling it, which has been reported not to work on macOS 26.5; if the filter never applies your profile, it is a limit of macOS and not of your setup.
- **Scripts run as you, with holzBar's permissions.** Whether an allowed script can use holzBar's own Accessibility and Screen Recording grants has not been measured on a Mac yet; until it is, treat an allowed script as being as powerful as holzBar. Malware that already runs as you can write a script and its approval too.
- A before hook cannot cancel a profile. Undoing the deletion of a profile brings it back without its hooks. A start or end script that is skipped is not tried again until the rule changes again.
- A VPN is seen only when the traffic goes through a tunnel. On macOS 27 a rule that shows one item moves all items of its app.
- Widgets: the macOS 26 recognition of a widget's window, script widgets and the energy cost are not verified on a Mac; a script widget follows system events only while an enabled rule follows them; on macOS 27 Show When It Changes does nothing for a widget.
- The expanded state of macOS 27's overflow button is recognised from the public description and the frames macOS reports, and whether concealing again moves the expanded icons is being checked.
- Sections is not available on macOS 27, where macOS decides the order of the items; a Sections choice is drawn as Paired there. The menu bar styles are drawn from the positions macOS reports.
- Drag in the menu bar: while it is on, an app's menu opens when you release the click rather than when you press, and pressing an item and sliding to the next one moves the item instead of opening the next menu. Apple's own items still move only with ⌘; holzBar's items, ⌥ Option and ⌃ Control clicks and double-clicks work as before. It does nothing on a full-screen Space, while macOS hides the menu bar, and for a moment after a drop.
- The accessibility changes were not checked with VoiceOver, Full Keyboard Access and Voice Control on a Mac; the [checklist](https://github.com/holzcloud/holzBar/blob/main/docs/accessibility-checklist.md) lists what to check. The glass section cards of Menu Bar Layout were not yet looked at on a Mac.
- Double-clicking a shared profile in Finder is not set up; use **Import Profile…** in Menu Bar Layout.
- The AppleScript dictionary, animations, more triggers (Bluetooth, audio, Energy Mode) and settings sync come in later releases.
- The other known issues of [0.0.7](https://github.com/holzcloud/holzBar/releases/tag/v0.0.7) still apply.

### 📦 Install
Update an installed holzBar:
```sh
brew update && brew upgrade --cask holzbar
```

If you installed the beta channel (`holzbar@beta`), switch to the stable one: `brew uninstall --cask holzbar@beta`, then use the commands below.

New install (quit the original Ice, Thaw, Bartender or Hidden Bar first if one of them is running):
```sh
brew tap holzcloud/holzbar https://github.com/holzcloud/holzBar
brew trust --cask holzcloud/holzbar/holzbar
brew install --cask holzbar
```

If macOS says holzBar can't be opened, take it out of quarantine and open it again:
```sh
xattr -dr com.apple.quarantine /Applications/holzBar.app
```

This release is signed with the same certificate as 0.0.6, 0.0.7 and the 0.0.8 betas, so updating keeps the Accessibility and Screen Recording permissions. Coming from 0.0.5, follow "Install and update" in the [0.0.6 notes](https://github.com/holzcloud/holzBar/releases/tag/v0.0.6).

holzBar runs on macOS 14 Sonoma and later, up to macOS 27. Only macOS 26 and 27 are tested.
