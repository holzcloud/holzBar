<objective>
Make the macOS 26 menu bar item service accept holzIce's ad hoc builds while it keeps rejecting every other process (BUG-06, D-02).

Purpose: the listener in the XPC service and the app's session both require a peer "from the same team". holzIce's releases and source builds are signed ad hoc and have no team identifier at all, so on macOS 26 the service can refuse holzIce itself; the app then falls back to its slower in-app lookup (the open "Loading menu bar items…" / `XPCRichError` reports in `docs/upstream-bugs.md`).
Chosen option (D-02, safest that works ad hoc): for code without a team, Apple's implicit designated requirement is its code directory hash (cdhash). The service therefore requires holzIce's signing identifier and one of the cdhashes of the app bundle it is embedded in: exactly that app's code is accepted, and every other process is rejected, including other ad hoc code that claims the same identifier. A team-signed build keeps the team check and adds the signing identifier. The hash reading is proven on the CI runner by a Swift Testing suite before the listener uses it.
Output: `Shared/CodeSigning/CodeSignature.swift` and its test target, the new listener requirement, the client session change, the updated `docs/upstream-bugs.md` row.
</objective>

API facts checked against Apple's documentation while planning (2026-10-02). Do not re-derive them:
- `XPCPeerRequirement` (XPC, macOS 26.0): `static func isFromSameTeam(andMatchesSigningIdentifier: String? = nil)`, `static func codeRequirement(_ requirement: ProcessCodeRequirement)`, plus entitlement and platform-code variants. `XPCListener(service:targetQueue:options:requirement:incomingSessionHandler:)` drops requests that do not satisfy the requirement; `XPCSession.setPeerRequirement(_:)` must be called once, on an inactive session.
- LightweightCodeRequirements (macOS 14.4): `ProcessCodeRequirement.allOf { ... } throws` (result builder over `ProcessConstraint`s; it throws when the same constraint type appears twice), `SigningIdentifier(String)`, `CodeDirectoryHash(Data)` and `CodeDirectoryHash.in([Data])` (match any of the listed hashes; Apple recommends a list because the chosen code directory differs per architecture), `TeamIdentifier(String)`, `ValidationCategory(.none)` means ad hoc. `SecCodeCheckValidityWithProcessRequirement(code:flags:requirement:)` (macOS 15.0) returns a `ValidationResult` with `signatureIsValid`, `requirementMatched` and `failureReason`.
