# Phase 05.1.1 Plan 03: macOS 27 second display and notch, no screenshots under the bar, launch grace, rest of #1001, docs Summary

On macOS 27, hit tests on the display whose bar is not active use the frames MenuBarAgent draws there, holzBar's icon is kept out from under the notch by a transient concealment, folded items get a re-layout on a roomier display and the overflow button is bridged; the wallpaper beside a shape comes from the desktop picture file (no capture on 27, a file watcher instead of a timer), the clock click is covered, apps launching into a concealed section get a grace until their item exists, the search opens hidden items through `ItemClicker27`, bundleless items are disabled, settings without effect are hidden, a dropped icon is put back, and the upstream bug list and README describe the phase.

## What was done

### Task 1 (tracer): second display and notch (THAW-04, ICE-04 frames) — 0bf1ff2
- `MenuBarItemProvider27.lastDrawnFramesByDisplay` / `drawnFrames(for:)`: every frame MenuBarAgent draws on displays whose bar is not active.
- `ItemHitTest27.isInsideItem` / `isInsideItemsArea` take `drawnFramesOnDisplay` (default empty; existing tests unchanged); `AccessibilityBackend27` passes the frames of the display under the point. Show on click, hover and the secondary context menu no longer fire on items of the second display (Thaw #1159, #1138, #1137).
- `NotchCover27.appsToConceal` and `adding(_:to:)` (tested). `Concealer27.checkNotchCover()` after each settled read: one visible app right of an icon under the notch joins a transient `notchConcealed` set (part of the target, never saved); cleared on active display change, screen change, app launch and quit. A move of the bar to a display without a notch or a wider one with folded items re-applies concealment once (`suspend` for the 400 ms settle; Thaw #1106).
- The bridge adds the overflow button frame to the system frames (Thaw #1195); test "A click on the overflow button is bridged while concealing".

### Task 2: no screenshots under the bar, clock cover, launch grace (THAW-06, ICE-03, ICE-04 wallpaper owner) — cf4ce50
- `DesktopPicture`: `desktopImageURL(for:)` + `desktopImageOptions(for:)`, ImageIO thumbnail at the screen's pixel size on a utility queue, laid out like the desktop (fill/fit/stretch/centre, fill colour), strip under the bar; cached per display by file, modification date and layout; `cachedStrip`, `isReadable(on:)`.
- `WallpaperChangeMonitor` (adapted from Thaw, NOTICE): `DispatchSource` on the wallpaper store's `Index.plist`, re-opened after every event (one 500 ms retry), debounced 500 ms.
- Overlay: wallpaper from `DesktopPicture`; only before macOS 27 with Screen Recording granted does a moving wallpaper fall back to the capture, and only then does the 30 s refresh run; on 27 the shape stands on `flatColor27()`. No wallpaper work without a shape.
- `ScreenRecordingFeature.menuBarShape` reason and summary name the moving wallpaper; the editor's hint shows only before 27 and only when the desktop picture cannot be read.
- `MenuBarSearchModel` uses `flatColor27()` on 27; `WindowInfo.wallpaperWindow` accepts `com.apple.WindowManager`. After this, nothing on 27 captures the wallpaper (D-02).
- `ClockCover27`: a non-activating panel above the status level over the concealed part of the bar (application menu end or notch to the drawn left edge), drawing the cached desktop-picture strip (flat colour otherwise) and a solid tint; shown right before `suspendReleased`, hidden 300 ms after the replay; never for a dismissing click.
- `LaunchGrace27` (3 tests): `Concealer27` shows an app launching into a hidden or always-hidden section until `AccessibilityBackend27.cacheFromLayout` sees its item, or 10 s (one bounded sleep), then ends the allowance once.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Default arguments keep Plan2Core27Tests untouched**
- **Found during:** Task 1
- **Issue:** `isInsideItemsArea` is called in `Plan2Core27Tests`, which must stay untouched.
- **Fix:** `drawnFramesOnDisplay: [CGRect] = []` on both hit-test functions.
- **Commit:** 0bf1ff2

**2. [Rule 1 - Bug] The clock cover never waits for a decode**
- **Found during:** Task 2
- **Issue:** Decoding the desktop picture inside the bridge would delay the held-back click.
- **Fix:** The cover draws the cached strip (`DesktopPicture.cachedStrip`) or the flat colour, and refreshes the cache for the next click.
- **Commit:** cf4ce50

**3. [Rule 1 - Bug] File watcher without Sendable captures of the dispatch source**
- **Found during:** Task 2
- **Issue:** Thaw's monitor captures the dispatch source in its own handler, which Swift 6 may reject.
- **Fix:** The handler only calls back on the main actor; the watch is opened anew after every event (the file is replaced atomically anyway).
- **Commit:** cf4ce50

**4. [Rule 2] No wallpaper decoding without a shape**
- **Found during:** Task 2
- **Issue:** The wallpaper was updated for every overlay configuration, though only shapes draw it.
- **Fix:** The overlay reads it only while a shape is chosen and reads it when one is chosen.
- **Commit:** cf4ce50

**5. Plan wording: one commit for Task 3**
- Task 3's code and docs were committed separately (`fix` and `docs`) so each commit's type is right.
