# Phase 05.1.1 Plan 01: Input never waits on another app; robust monitors, moves, sleep and appearance; hardened hotkeys and colours Summary

holzBar no longer asks another app through Accessibility on any input path: an off-main `ApplicationMenuFrames` cache (0.25 s per-element timeout) serves show on click, hover, the context menu, hiding application menus, temporary showing and the overlay; event taps rebuild invalid ports, automatic moves back off (adapted from Thaw's MoveCircuitBreaker), holzBar rests while the Mac is locked or asleep and settles 2 s after, the menu bar look stands on every desktop, and hostile stored hotkeys and colours are rejected without a trap.

## What was done

### Task 1 (tracer): show on click from cached state, nothing on the input path waits (THAW-07, THAW-05) — d7a8a86
- `holzBar/MenuBar/ApplicationMenuFrames.swift`: `@MainActor @Observable` cache owned by `AppState`. Reads every screen's application menu frame and whether its menu bar window is an Accessibility menu bar, on a private serial queue; a newer read replaces an older one (generation counter). Triggers: KVO of `frontmostApplication` and `menuBarOwningApplication`, `activeSpaceDidChangeNotification`, `didChangeScreenParametersNotification`, setup; each trigger reads now, after 150 ms and after 600 ms, then stops.
- `getApplicationMenuFrame()` moved to the `Sendable` `ApplicationMenuQuery` (built on the main actor from `NSScreen.applicationMenuQuery`), documented as blocking; it is called only from `ApplicationMenuFrames.swift`.
- `AXHelpers`: `applicationMenuTimeout = 0.25`, `application(for:messagingTimeout:)`, `setMessagingTimeout(_:for:)`; `applicationMenuBar(at:)` and every child read of the application menu use the 0.25 s timeout. The XPC service keeps the default.
- Readers switched to the cache: `MenuBarHitTesting.isMouseInsideApplicationMenu`, `MenuBarManager` (hiding application menus), `MenuBarItemManager.temporarilyShow`, the overlay (observes `frames` with `ObservationLoop`; its 1 ms / 1 s read loop is gone; a click only asks for one off-main refresh).
- `MenuBarManager.hasValidMenuBar(in:for:)` (overlay validation, reached from clicks through the overlay's updates) reads validity from the cache instead of a main-thread system-wide hit test.
- `MenuBarItemProvider27.currentBounds(for:)`: on the main thread answers from the last read.
- Show on click logs `Show on click: revealed N ms after the click` (debug) after the toggle (on macOS 27 after `Concealer27.update()`).

### Task 2: taps recover, moves back off, holzBar rests (THAW-03) — 25fd4fc
- `SystemActivity` (Core): lock / sleep / session flags, `isPaused`, `settled(at:)` 2 s after unlock, wake, session return or a display change. 5 tests.
- `MoveBackoff` (Core, adapted from Thaw's `MoveCircuitBreaker`): window 60 s, same-item limit 4 (5th trips), 8 failures trip, pause 60 s doubling to 600 s, reset 300 s after the last pause ended, user moves clear it. 6 tests.
- `SystemActivityMonitor` (`AppState.systemActivityMonitor`): notification Tasks for workspace sleep/wake/screens sleep/wake/session, `com.apple.screenIsLocked`/`Unlocked`, screen parameters; one bounded `settleDelay` sleep per resume; `onSettled` handlers.
- While paused: no item list reads, no `cacheItemsRegardless`, no `placeNewItems`, no automatic move, no image capture (both backends), `Concealer27.update()` leaves assertions as they are. On settle (`AppState.systemActivityDidSettle`): `HIDEventManager.healthCheck()`, `concealer27.update()`, `appearanceManager.systemActivityDidSettle()`, `cacheItemsRegardless()`, `retryPausedRehide()`, `imageCache.updateCache()`.
- `EventTap` keeps its creation parameters, `recreateIfInvalid()`, `enable()` recreates, adds the run loop source, then enables. `EventMonitor.restart()`. `HIDEventManager.healthCheck()` repairs running taps and monitors and restarts the macOS 27 click bridge; it also runs when Accessibility turns granted.
- `MenuBarItemManager.move(item:to:origin:)` with `MoveOrigin.user/.automatic`; the Layout pane and `temporarilyShow` pass `.user`. Automatic moves throw `EventError.automaticMovesPaused` while paused ("Automatic moves paused until N s from now" logged once per pause). Rehiding waits during a pause (retried on settle, on a user move after the usual interval, or once when the pause ends) instead of retrying every 3 s without end.
- NOTICE credits Thaw's `MoveCircuitBreaker.swift`.

### Task 3: appearance follows the icons and survives sleep and login; hotkeys and colours validated (THAW-03, ICE-01) — 22b2d33
- Overlay: `collectionBehavior = [.fullScreenNone, .ignoresCycle, .canJoinAllSpaces, .stationary]`, no re-show on space change (wallpaper update kept); redraws on sections' `isHidden`, `itemManager.itemCache` and (macOS 27) `concealer27.concealedPIDs`; fades to alpha 0 on a fullscreen space and back.
- `MenuBarAppearanceManager.systemActivityDidSettle()` rebuilds when the screens changed or a panel found no menu bar, else refreshes; panels that found no menu bar at launch are retried at most 3 times, 3 s apart.
- `HotkeyStorage.isValid(key:modifiers:)` (0...127, only the four known modifier bits); `decode` and `KeyCombination.init(from:)` reject the rest; `KeyCode.keyEquivalent` uses `UInt16(exactly:)`; `HotkeyRegistry` uses `UInt32(exactly:)` and logs instead of trapping; `HotkeysSettings` ignores and logs invalid or system-reserved stored combinations. 2 new tests.
- `ColorComponents.isValid` / `clamped` (Core, 3 tests); `HolzBarColor.init(from:)` throws on a wrong count or non-numbers; `HolzBarGradient.averageColor` converts to the RGB space, skips colours without four components and returns nil when none is left.
- `privacy-check.py` PERSONAL_DATA gains `window title` (`title|windowTitle|kCGWindowName`); probed: a public `window.title` fails the check; the tree has no hit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] No messaging timeout on the system-wide element**
- **Found during:** Task 1
- **Issue:** `AXUIElementSetMessagingTimeout` on the system-wide element sets the global timeout of every Accessibility call in the process (Apple's AXUIElement.h); 0.25 s globally would cut short the macOS 27 item scan's child reads and the item presses.
- **Fix:** The 0.25 s timeout is set on the menu bar element and on each child read; the pre-27 system-wide hit test keeps the default, which is harmless now that it runs off the main thread.
- **Commit:** d7a8a86

**2. [Rule 1 - Bug] No shorter timeout on macOS 27 item elements read off the main thread**
- **Found during:** Task 1
- **Issue:** `ItemClicker27` presses the same `AXUIElement`; a 0.25 s timeout set on it would make a press that waits for the item's menu fail.
- **Fix:** Off the main thread `currentBounds` reads live with the element's existing timeout; on the main thread it answers from the last read (the plan's main requirement).
- **Commit:** d7a8a86

**3. [Rule 2 - Missing critical] Menu bar validity off the main thread**
- **Found during:** Task 1 audit
- **Issue:** `MenuBarManager.hasValidMenuBar` ran a system-wide Accessibility hit test on the main thread for every overlay update, reached from clicks through the overlay.
- **Fix:** `ApplicationMenuFrames` also caches whether each display's menu bar window is a menu bar; the overlay updates once its display becomes valid.
- **Commit:** d7a8a86

**4. [Rule 1 - Bug] MoveBackoff reset measured from the end of the pause**
- **Found during:** Task 2 (tests)
- **Issue:** Measured from the last trip (as in Thaw), a 480 s pause always exceeds the 300 s reset, so the pause could never reach the 600 s cap the behaviour requires.
- **Fix:** Reset when 300 s passed after the last pause ended; the pause doubles 60, 120, 240, 480, 600, 600.
- **Commit:** 25fd4fc

**5. [Rule 1 - Bug] Plan test values for hotkeys contradicted the modifier rule**
- **Found during:** Task 3
- **Issue:** The behaviour list says `[0, 256]` and `[127, 256]` decode, but 256 is an unknown modifier bit, which the next behaviour rejects.
- **Fix:** The key-code test uses modifier 8 (Command); unknown-bit cases (256, 16, -1) are in the modifier test.
- **Commit:** 22b2d33

**6. [Rule 1 - Bug] Colours slightly outside 0...1 clamped, not rejected**
- **Found during:** Task 3
- **Issue:** Colours picked in an extended colour space can be stored slightly outside 0...1; rejecting them would fail the whole appearance configuration's decoding and reset the user's look.
- **Fix:** `ColorComponents.clamped` before `isValid`; wrong counts, NaN and infinity are still rejected (tests per the plan plus one for clamping).
- **Commit:** 22b2d33

**7. [Rule 2] Rehide wait ends with the pause**
- **Found during:** Task 2
- **Issue:** With only "next settle or user move", shown items could stay out until the next lock/unlock.
- **Fix:** One bounded timer fires as the back-off pause ends (D-03: not a loop).
- **Commit:** 25fd4fc
