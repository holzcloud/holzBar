# Phase 05.1.1 Plan 02: Item identity and one restore path; menus, clock clicks, Dock icon, notch apps; Shelf clicks, spacing and URL audit Summary

Items keep one identity when their titles change (numbers canonicalised, title-changing apps learned and keyed by position, several items of one app kept apart), and before macOS 27 their sections are saved and restored through the single `reconcileSections` path; only menus delay rehiding, the macOS 27 clock bridge stays inside the visible bar, Settings and the search no longer show a Dock icon, notch apps above the bar are left alone, Shelf clicks on macOS 26 find the application menu, respawning apps are relaunched once, and `holzbar://profile/<name>` asks first.

## What was done

### Task 1 (tracer): identity and the one restore path (THAW-01) — fcc2226
- `ItemIdentity` (Core): `canonicalTitle` (digits → `#`, byte units normalised; identifier-like titles kept), `learnTitleChangingOwners(previous:current:excluding:)`, `keys(for:titleChangingOwners:)` (`ns:#1`, `ns:#2` for learned apps; `ns:title`, `ns:title:2` for duplicates), `storedKey` (old raw keys canonicalised; keys of this version kept). 5 tests.
- `Defaults.Key.itemSections` (`ItemSections`, dictionary) and `titleChangingItemOwners` (`TitleChangingItemOwners`, string array), with kinds.
- `MenuBarItemManager`: learns title-changing apps after each pre-27 cache (persisted), keeps identity keys per window; `identityKey(for:)` / `storedIdentityKey(_:)` are the only way items become stored keys.
- `SectionRestore.swift`: `saveSections()` (after a Layout drop, a Command-drag, first run), `storeSections(_:)` (profile, placed new items), `saveSectionsSoon()` (one bounded re-read 1.5 s later), `reconcileSections(wanted:trigger:)` — the one path: profile sections, saved sections (launch, app launch + one 2 s re-check, settle) and new items (every item list change); skipped while dragging, while paused, while a save is pending; a second call during a run runs once afterwards; moves are automatic (MoveBackoff). Live Activities logic moved here. `placeNewItems` and `move(itemsTo:)` removed.
- Profiles save identity keys and apply through `reconcileSections`; groups toggle/contain/list by identity (settings pane uses `groups.contains`); `KnownItemTags` holds identity keys; temporarily shown items are found by window, then identity.
- `InputMonitors.Settings.savesUserArrangement` (tested): before macOS 27 the mouse-up monitor runs so a Command-drag on the bar is noticed even without the drag monitors.
- NOTICE credits Thaw's `canonicalMetricTitle`.

### Task 2: menus, clock, Dock icon, notch apps (THAW-02, ICE-02 #933) — e20fe55
- `InterfaceWindowRule` (levels 24, 25, 100, 101; owner's new window): `isShowingInterface` and the recorded interface window use it; macOS 27 `ItemClicker27.windowOwners()` lists only menus. 2 tests.
- `ClockBridgeZone27.shouldBridge(...menuBarRect:)`: nil or outside the rect → no bridge; frames grow by 1 pt horizontally only. `SystemItemClickBridge27` passes the clicked display's bar rectangle (strip above the visible frame, at least the status bar's thickness; on a fullscreen space only while the WindowServer menu bar window is on screen). Existing 4 test names kept, plus "A click just below the bar is not bridged" and "Nothing is bridged while the bar is hidden".
- `DockIconPolicy` (settings/search → accessory, permissions → regular, hideApplicationMenus → regular or nil per setting, toggleApplicationMenus → regular). 4 tests. `AppState.activate(for:)` replaces every `activate(withPolicy: .regular)` caller; `activate(withPolicy:)` is private. New setting "Keep the Dock icon hidden" (`KeepsDockIconHidden`, default on) under "Hide app menus…" with the planned annotation.
- `MenuBarOcclusion` (another non-system app's visible window above layer 25 containing the point). 4 tests. `isMouseInsideEmptyMenuBarSpace` checks it last, reading the window list at most every 0.25 s; windows as wide as the display (overlays) are ignored.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Identifier titles keep their digits**
- **Found during:** Task 1
- **Issue:** Canonicalising every digit turned `Item-0`/`Item-1` (the titles of several status items of one app) into one title, making their identities depend on bar order.
- **Fix:** Titles that are identifiers keep their digits; tests cover it.
- **Commit:** fcc2226

**2. [Rule 2 - Missing critical] User arrangements are saved before any restore**
- **Found during:** Task 1
- **Issue:** Command-drags were only noticed when the drag monitors ran (two settings); a restore triggered by an app launch would have undone the user's move.
- **Fix:** `saveSectionsSoon()` with a bounded re-read; restores wait while a save is pending; the mouse-up monitor (one event per click) runs before macOS 27 (`savesUserArrangement`, tested).
- **Commit:** fcc2226

**3. [Rule 1 - Bug] Item list changes place new items only**
- **Found during:** Task 1
- **Issue:** Restoring saved sections on every cache update would fight the user and macOS; the plan's triggers did not cover new items added by already running apps.
- **Fix:** `.itemListChange` places new items only; saved sections are restored on the plan's triggers.
- **Commit:** fcc2226

**4. [Rule 1 - Bug] The application-menu toggle still works**
- **Found during:** Task 2
- **Issue:** With "Keep the Dock icon hidden" on by default, the "Toggle application menus" hotkey and URL would silently do nothing.
- **Fix:** `DockIconPolicy.ActivationReason.toggleApplicationMenus` → regular (the user asked); automatic hiding follows the setting.
- **Commit:** e20fe55

**5. [Rule 1 - Bug] Clock bridge rectangle off fullscreen without the window list**
- **Found during:** Task 2
- **Issue:** Requiring the WindowServer menu bar window everywhere could disable the bridge on macOS 27 if that window is absent; reading it in the active tap for every click is also costly.
- **Fix:** Off fullscreen the rectangle is the strip above the screen's visible frame (at least the status bar's thickness); the window list is read only on a fullscreen space and only while concealing.
- **Commit:** e20fe55

**6. [Rule 1 - Bug] Apple menu at the probe points**
- **Found during:** Task 3
- **Issue:** Points 8–40 pt in usually hit the Apple menu (`AXMenuBarItem`), not the bar.
- **Fix:** The corner pixel is tried first, and a menu bar item leads to its parent bar.
- **Commit:** c194bfc

**7. [Rule 1 - Bug] Escape and the default button of the profile question**
- **Found during:** Task 3
- **Issue:** One NSButton holds one key equivalent, so Cancel cannot be both Return and Escape.
- **Fix:** Cancel is the first (Return) button; a local key monitor during the modal aborts it on Escape (any answer but Apply cancels).
- **Commit:** c194bfc
