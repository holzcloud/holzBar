# Phase 05.1.1.1 Plan 01: Zen mode, Shortcuts actions, hotkeys per profile and item, profiles per display or Space Summary

Zen mode keeps hidden items hidden from a hotkey, holzBar's menu, `holzbar://zen/toggle`, a Shortcuts action and, optionally, automatically while the screen is mirrored or shared (no permission, no polling); five App Intents with App Shortcuts expose Zen mode, sections, profiles, opening and searching items; every layout profile and every menu bar item can have its own hotkey; and profiles can be bound to a display or a Space.

## What was done

### Task 1: Zen mode (THAW-10) — c0f0abc
- `ZenMode` (Core): manual and automatic parts, `isActive`, `allows(_:)` per trigger (hover, empty-bar click, scroll, reveal rule, URL command, change reveal, holzBar icon, section hotkey), `toggled()`; 4 tests.
- `MenuBarManager.toggleZenMode()`, `setAutomaticZenMode(_:)`; turning it on hides every section; the state and its cause are logged publicly (no personal data).
- Gates in `HIDEventManager` (hover, click, scroll), `RevealRules.reveal`, `URLCommands` (logs "Ignored: Zen mode").
- `HotkeyAction.toggleZenMode` (raw value `ToggleZenMode`, appended to the pinned list), `holzbar://zen/toggle` (no confirmation; test), "Zen Mode" item with a checkmark in holzBar's menu.
- `ToggleZenModeIntent` and `HolzBarShortcuts`.

### Task 2: Zen mode while presenting, hotkeys per profile and item, Shortcuts actions (THAW-10, THAW-15) — 6f882b0
- `PresentationSignals` (Core, tested) and `PresentationMonitor`: stored Tasks on screen-parameter changes, app launch and app termination; runs only while "Turn on Zen mode while the screen is mirrored or shared" (`AutoZenWhileSharingScreen`, Advanced) is on; turning the setting off withdraws only the automatic part.
- `HotkeyTarget` (Core, tested): `.action`, `.applyProfile(name)`, `.openItem(identityKey)`; `Hotkey` holds a target; `HotkeysSettings` keeps dynamic hotkeys keyed by target, moves a profile's hotkey on rename and removes it on delete.
- Hotkeys pane: a "Layout Profiles" section with a recorder per profile, item hotkey rows with a remove button, recorders for Zen mode and (plan 02) "Open an item by letter". Layout items: "Set Hotkey…" in their context menu.
- `ItemOpener`: one place that opens an item (used by hotkeys and intents here, by every caller in plan 02).
- Intents: `ChangeSectionIntent`, `ApplyLayoutProfileIntent` (with `LayoutProfileEntity`/`LayoutProfileQuery`), `OpenMenuBarItemIntent` (fuzzy match), `SearchMenuBarItemsIntent`; five App Shortcuts, each phrase with `\(.applicationName)`.

### Task 3: profiles bound to a display or a Space (THAW-11) — 42b1e81
- `ProfileBinding` (Core, 4 tests): `displaysConnected(_, activeSpace:)` and `spaceChanged`, `newlyConnected`; the Space wins over the display.
- `Bridging.getDisplayUUIDString(for:)`, `getActiveSpaceUUID()` (shim `CGSCopyManagedDisplaySpaces`; fallback `FirstSpace:<id>`).
- `LayoutProfiles`: bind, unbind, rename, apply after the display settles or on a Space change; no apply while a layout drag runs.
- Layout pane: profile rows with Apply, a Bind menu (to this display, to this Space, unbind), Rename… and Delete… (confirmation).
- README rows and features, Raycast README (Zen mode command, Shortcuts paragraph), NOTICE (PresentationMonitor adapted from Thaw).

Not confirmed on a Mac (no Mac here). ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `ItemOpener` created in this plan**
- **Found during:** Task 2
- **Issue:** Item hotkeys and the Open Menu Bar Item intent need to open an item; plan 02 was to create the single open path.
- **Fix:** `ItemOpener` was created here and plan 02 moved the remaining callers onto it.
- **Commit:** 6f882b0

**2. [Rule 1 - Bug] App Intents could not find the app**
- **Found during:** Task 2
- **Issue:** With `@NSApplicationDelegateAdaptor`, `NSApp.delegate` is a SwiftUI object, not `AppDelegate`.
- **Fix:** `AppState.current` (weak, set in `AppDelegate.init`).
- **Commit:** 6f882b0

**3. `openAppWhenRun` omitted**
- holzBar is a menu bar app that runs already; the intents act in place, so no intent asks to open the app.

## Open human checks (macOS 26 and 27)
- Zen mode from holzBar's menu: hidden items hide; hovering, clicking empty bar space and scrolling reveal nothing, a low-battery or offline rule does not reveal, `open holzbar://show/hidden` is ignored; clicking holzBar's icon and the section hotkey still show them. The Zen mode hotkey and `open holzbar://zen/toggle` toggle it; Shortcuts lists "Toggle Zen Mode" and it works.
- "Turn on Zen mode while the screen is mirrored or shared": mirroring a display (or AirPlay mirroring) and another Mac sharing this screen turn Zen mode on, ending them turns it off; confirm the sharing agent with `lsappinfo list | grep -i screensharing` during a session.
- A profile and an item with a hotkey: the profile applies and the item's menu opens from the keyboard; both survive a relaunch and an export/import.
- Shortcuts: "Apply Layout Profile" lists the profiles; "Change Section", "Open Menu Bar Item" (by name) and "Search Menu Bar Items" work.
- Bind a profile to an external display, unplug and replug it: the profile applies once; bind one to a Space and switch Spaces: it applies; after a restart the bindings still work.
