<objective>
Validate every imported or synced settings dictionary against holzBar's own keys and types (SEC-01), log URL commands without their URL (SEC-02), and keep captured item images in Caches instead of Application Support, moving the existing ones (SEC-03).

Purpose: `SettingsBackup.apply` and the Ice import write every key a plist or the iCloud file contains, so a crafted file can set any `NSUserDefaults` key the app or AppKit reads; URL commands log full URLs publicly; screenshots of other apps' menu bar items (message counts, VPN state) are kept in Application Support and so in every backup.
Output: `Defaults.swift` moved into Core with value kinds, `SettingsSchema` with tests, validated import/sync/Ice paths, URL logging by command, `ItemImageFolder` with tests and the Caches location.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings file chosen by the user → holzBar defaults | The file can come from anywhere |
| iCloud Drive file → holzBar defaults | Written by any Mac (or process) with access to the user's iCloud Drive |
| Ice's defaults domain → holzBar defaults | Another app's settings |
| holzBar → backups | Files in Application Support are backed up; Caches are not |
| holzBar → unified log | Log lines can be read by admin users and sysdiagnoses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | `SettingsBackup.apply`, iCloud pull, Ice import | high | mitigate | Only Defaults.Key raw values with the declared kind are applied; others ignored and counted; exhaustive kind switch; tests (Task 1) |
| T-05-02 | Information Disclosure | Settings export and iCloud file | medium | mitigate | `currentSettings()` exports only holzBar's keys, not window frames or panel paths (Task 1) |
| T-05-03 | Information Disclosure | URL command logging | medium | mitigate | Only the command name is logged; URL and arguments (profile names) never (Task 2) |
| T-05-04 | Information Disclosure | Item images in backups | medium | mitigate | Stored under Caches, existing ones moved, old folder removed when empty (Task 2) |
| T-05-05 | Denial of Service | Image move at launch | low | mitigate | A rename on the same volume; failure is logged and the store starts empty, as after a version change (Task 2) |
| T-05-SC | Tampering | Package.swift / dependencies | low | mitigate | No package added or upgraded; no npm/pip/cargo install, so no package-legitimacy checkpoint applies |
</threat_model>
