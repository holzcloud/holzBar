## Final shape of importPreviousSettingsIfNeeded()

- **Called** first thing in `AppDelegate.init`, before `SettingsSync.pullIfNeeded()` (which reads the copied sync file) and before `AppState()` (which reads the settings).
- **Guard order** unchanged: return when `HasImportedIceSettings` (now `Defaults.Key.hasImportedPreviousSettings`) is set; read holzBar's own domain; set the flag; return unless the own domain was empty. So it runs once, and only into empty settings.
- **Precedence:** `previousApps` = holzIce (`com.holzcloud.holzIce`, folder `holzIce`), then the original Ice (`com.jordanbaird.Ice`, no folder). The first app whose defaults domain is non-empty is imported; the loop then returns, so Ice is never imported when holzIce has settings.
- **Settings:** every key except those starting with `SettingsBackup.excludedKeyPrefixes` (`NSWindow Frame`, `NSStatusItem Preferred Position`, `NSStatusItem Visible`, `SU`); the comment about the macOS 27 lock-up stays. Logged as `Imported N of M settings from <name>` (public). holzIce's `HasImportedIceSettings` and `hasMigrated…` flags come along, so the old migrations do not rerun.
- **Files (holzIce only):** `~/Library/Application Support/holzIce` to `~/Library/Application Support/holzBar` (item images with their `version.txt`), and `iCloud Drive/holzIce/Settings.plist` to `SettingsSync.fileURL` (`iCloud Drive/holzBar/Settings.plist`), the latter only when iCloud Drive is on. Each copy happens only when the source exists and the destination does not; the destination's parent folder is created; success logged at notice level, failure with `logger.error` and the launch continues.
- **Never touched:** nothing of holzIce's or Ice's is moved, deleted or written (no `moveItem`/`removeItem` in the file); nothing holzBar already has is overwritten; Ice's files are not copied (its import stays settings-only).
