# Phase 28 — UI Design Contract

> Visual and interaction contract for Settings sync redesign (target 0.0.7-beta3). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a native macOS app. There is no CSS, no px grid and no component registry. The contract binds the phase to Apple's Human Interface Guidelines and to the patterns already in the app (`HolzBarForm`, `HolzBarSection`, `.annotation(...)`, `NSAlert.beginSheetModal`). Sizes are system text styles and points, colors are semantic system colors. The maintainer delegated every UI decision; every choice that was open is recorded under "Assumptions" at the end.

Sources pre-populated: `28-CONTEXT.md` (D-02, D-04, D-05, D-07 to D-10), `DECISIONS.md` (S-2 to S-6, defaults), `SYNC-REDESIGN-ANALYSIS.md` §4.7 and §4.8, `D1-per-device-files.md` §6.2, `D3-settings-only.md` §8, and the code as it is today: `holzBar/Settings/SettingsPanes/AdvancedSettingsPane.swift` (`SettingsSyncToggle`), `holzBar/Utilities/SettingsSync.swift` (`makeAlert`, `chooseFolder`), `holzBar/MenuBar/ControlItem/ControlItem.swift` (`createMenu`), `holzBar/Settings/SettingsPanes/MenuBarLayoutSettingsPane.swift` (`LayoutProfilesSection`).

## Spacing Scale

macOS has no spacing tokens; the contract is the values the existing panes already use, plus the sheet's own.

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Gap between a value and its date line in the sheet; glyph-to-text gaps |
| sm | 8pt | Sheet row vertical padding; button gaps (`HStack` default) |
| md | 16pt | Sheet column gap; gap between the row list and the body or footer text |
| lg | 24pt | Not used |
| xl | 32pt | Not used |
| 2xl | 48pt | Not used |
| 3xl | 64pt | Not used |

Sheet geometry: accessory width 480pt; row list scrolls above 240pt of height (about five two-line rows); column widths Setting flexible (minimum 160pt), This Mac 120pt, Sync folder 160pt.

Exceptions (inherited from existing code, not changed by this phase): `HolzBarForm` spacing 10 and padding 20; the label stack in `SettingsSyncToggle` and `.annotation` use spacing 2. New status lines go into that existing 2pt label stack; they add no new spacing value.

Touch targets: not applicable (pointer-first macOS); every control keeps its system control size. No `controlSize` overrides in the sheet.

## Typography

System text styles on macOS: Body is 13pt, Subheadline is 11pt. No other size is introduced; the sheet's title and body are `NSAlert`'s own styles (13pt, title semibold).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13pt (`.body`) | Regular (400) | System default; never set `lineSpacing` |
| Label (row labels in the sheet, button titles) | 13pt (`.body`) | Regular (400) | System default |
| Subheadline (status lines, annotations, sheet column headers, dates, footer) | 11pt (`.subheadline`) | Regular (400) | System default |
| Heading (section header "Settings", `NSAlert` title) | 13pt (`.headline` / `NSAlert.messageText`) | Semibold (600) | System default |

Two distinct point sizes and two weights, on purpose: macOS panes use text styles, not a size ladder. A fourth size (Display) is not needed in this phase.

Rules: status lines and the sheet's dates and footer are `.subheadline` and `.secondary` (existing pattern in `SettingsSyncToggle`). Use `.monospacedDigit()` for counts that change while visible ("%lld files"). Long text wraps (status lines, body); in the sheet's table cells it truncates at the tail after two lines, with the full text in `.help(...)` and in the VoiceOver label.

## Color

Semantic system colors only; no hex values. The app adapts to light, dark and increased-contrast automatically.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `windowBackgroundColor` | Settings window and sheet background |
| Secondary (30%) | `HolzBarSection` group-box fill; `controlBackgroundColor` for the sheet's row list | Section container, sheet table |
| Accent (10%) | System accent color (`Color.accentColor`, the user's choice) | Keyboard focus ring and the highlighted item of an open pop-up menu only |
| Destructive | System destructive rendering of `NSButton.hasDestructiveAction` | "Use Settings from Sync Folder" and "Keep This Mac's Settings" in the sheet (existing; both replace a value and cannot be undone) |
| Warning text | `.orange` (existing precedent: folder not found) | Two status lines: folder cannot be found, a sync file can't be read |
| Secondary text | `.secondary` | Every other status line, annotations, column headers, dates |

Accent reserved for: the focus ring and an open pop-up's highlighted item. It is not used on text, on status lines, on the hint buttons or as a badge. The sheet has no default button, so no button is accent-filled (SA-07).

Never use red text for a status line: nothing here is data loss in progress. Never color the hint to draw attention (`modal-alerts-1`: quiet).

## Copywriting Contract

Voice: plain, short, no jargon (no "sibling", "dot", "register", "join", "MacID", "device file"). The other Mac is never named, only "another Mac" and a date (privacy, D-09). All strings are English in the repo; de (Swiss spelling, "ss" never "ß"), fr, it and rm are machine-written and must exist in `holzBar/Resources/Localizable.xcstrings` (`.github/scripts/strings-check.py` must pass, including plural variations and format specifiers). Strings with a count use String Catalog plural variations in every language, never "(s)".

### Existing strings that are reused unchanged

"Sync settings between your Macs", "Turn On…", "Change…", "Turn Off", "Restart", "Choose Settings…", "Settings changed on another Mac", "The sync folder cannot be found. Choose it again.", "Through %@", "Which settings should holzBar use?", "Use Settings from Sync Folder", "Keep This Mac's Settings", "Later", "Cancel", "Done", "Sync Here" and the `NSOpenPanel` message, "Visible", "Hidden", "Always Hidden", "Off", "None", "Hotkey", "Applied", "Delete the profile “%@”?".

### Primary actions

| Element | Copy |
|---------|------|
| Primary CTA (idle) | Turn On… |
| Primary CTA (a question waits) | Choose Settings… |
| Primary CTA (only a fast-forward waits) | Restart |
| Join in progress | Cancel |
| Sheet buttons, in this order right to left (AppKit order) | Use Settings from Sync Folder · Keep This Mac's Settings · Later (Cancel when joining) |

### Status lines (Settings → Advanced, under "Sync settings between your Macs"; and the quiet hint in holzBar's menu)

State, text, button, and where it shows. "Menu" means the section header at the top of holzBar's menu plus the button as a menu item.

| State | Text | Button | Menu | Tone |
|-------|------|--------|------|------|
| Folder chosen and found | Through <folder> (existing) | Change…, Turn Off | no | secondary |
| Folder cannot be found | The sync folder cannot be found. Choose it again. | Change… | no | orange |
| A join reads the folder, all files present | Reading the sync folder… (new) | Cancel | no | secondary |
| A join reads the folder, files still downloading | Reading the sync folder… (%lld files not downloaded yet) (new, plural) | Cancel | no | secondary |
| A join found rows to decide | Choose which settings this Mac uses (new) | Choose Settings… | yes | secondary |
| Another Mac's changes wait (fast-forward) | Settings changed on another Mac | Restart | yes | secondary |
| A conflict, hotkey clash or differing value on this Mac | Settings changed on another Mac | Choose Settings… | yes | secondary |
| A conflict between other Macs (bystander) | Your other Macs differ on %lld settings (new, plural) | Choose Settings… | no | secondary |
| Files waiting for download (not joining) | Waiting for %lld files in the sync folder to download. (new, plural) | none | no | secondary |
| A Mac with a newer format | A Mac uses a newer holzBar. Update holzBar to sync with it. (new) | none | no | secondary |
| A Mac on 0.0.6 or 0.0.7-beta1 still writes the legacy file | A Mac with an older holzBar still uses this folder. Update holzBar there to sync with it. (new) | none | no | secondary |
| A custom holzBar icon over 256 KiB | Your custom holzBar icon is too large to sync. (new) | none | no | secondary |
| A file that stays unreadable or too large (refused, retried) | A sync file in the folder can't be read. (new) | none | no | orange |
| A value from a newer holzBar | A setting from a newer holzBar can't be used here. (new) | none | no | secondary |

Rules:
- One button slot, in the existing `HStack` before Change…: Choose Settings… wins over Restart when both would show (existing behavior: `restartWithWaitingSettings` falls through to the question). After an answer that leaves fast-forwards waiting, the slot becomes Restart.
- Lines stack in the existing 2pt label stack in this order: folder line, state line (join, hint, bystander), then notes (waiting files, newer format, older holzBar, oversize icon, refused file, unusable value). Show every line that applies; each line is one sentence and may wrap. No icons, no badges, no counts in the sidebar, no alert, no notification, no sound, no Dock bounce, no automatic opening of the Settings window.
- During a join, Change… and Turn Off are hidden and Cancel is the only button. Cancel writes nothing; sync stays off, or keeps the previous folder after Change….
- The "older holzBar" line clears 30 days after the legacy file last changed (analysis §4.8). The "waiting for files" line is evaluated when the pane appears and when engine state changes; it never polls on a timer.
- Bystander conflicts, notes and warnings never appear in holzBar's menu (`modal-alerts-1`, analysis §4.7); only the three hint states marked "yes" do. In the menu, the header text is the state's text above and the item is its button ("Restart" or "Choose Settings…").
- The paused note ("Sync is paused in this beta and returns in the next one…") and the `.disabled(isPaused)` on the buttons are removed with the flip of `SettingsSyncPause.isPaused`; the old strings are deleted from the catalog.

### What sync covers: the annotation under the sync row (replaces today's string)

"Keeps your hotkeys, appearance and other settings the same on all your Macs through a folder they sync: iCloud Drive, Nextcloud, Dropbox, OneDrive, Syncthing or a network share. The menu bar arrangement and layout profiles sync only between Macs with macOS 27; on a Mac with macOS 26 they stay on that Mac. The folder's own app carries the files; holzBar never goes online. Changes from another Mac apply after a restart."

One string for both macOS versions. It is shown in every state (idle and on), as today, `.annotation` style.

## Surface Contracts

### 1. The quiet hint (`modal-alerts-1`: never a dialog by itself)

- A hint is text plus one button in Settings → Advanced and a header plus one item at the top of holzBar's menu. Nothing opens, steals focus, bounces the Dock, notifies or plays a sound.
- Publishing continues while a question waits (D-08); the hint says nothing about it.
- A sheet opens only from a click on Choose Settings…, or as the direct continuation of a join the user just started with Turn On… or Change… while the Settings window is on screen (existing behavior; the user's own action). A join started by holzBar (first launch after an update, untrusted state) only shows the hint.
- Later writes nothing, hides the hint until the next launch, and the sheet never reopens by itself.

### 2. The conflict sheet

- Mechanism: `NSAlert` with `beginSheetModal(for: settingsWindow)`, one at a time, no nested run loop. Rows live in an `NSHostingView` accessory (SwiftUI `ScrollView` + `Grid`, 480pt wide, at most 240pt high, rows separated by `Divider`).
- Order of rows: by the Settings window's sidebar order (General, Advanced, Hotkeys, Appearance, Groups, Items, Menu bar arrangement, Profiles), inside a category by `localizedStandardCompare` of the row label. Deterministic, never by date.
- Two-way rows: columns This Mac and Sync folder; the buttons decide.
- Rows with three or more values and all bystander rows: the This Mac and Sync folder cells merge into one pop-up (plain `Picker`, `.menu` style) listing every value with its date, no default selection (placeholder "Choose a Value"). Use and Keep (or Use Chosen Settings) stay disabled until every such row has a choice; the chosen value is what the answer writes for that row, whichever button is pressed. Later and Cancel stay enabled.
- Buttons: first button Use Settings from Sync Folder, second Keep This Mac's Settings, third Later or Cancel (joining) with Escape in every language (`keyEquivalent = "\u{1B}"`). `hasDestructiveAction = true` on the first two; no default button (first button `keyEquivalent = ""`, as today). Order right to left follows `NSAlert`, which is the HIG order.
- Focus: initial focus on the first undecided pop-up if any, otherwise the third button (never a destructive one). Full keyboard access: Tab visits pop-ups and buttons; Return does nothing; Escape closes with Later or Cancel.
- Footer text sits under the list inside the accessory view; the body is `informativeText`.
- An entry that arrives while the sheet is open does not change the shown rows; it survives and the hint returns afterwards (analysis §4.6.9).

### 3. Join flow (Turn On…, Change…)

1. Click Turn On… or Change…: existing `NSOpenPanel` (prompt "Sync Here").
2. Folder chosen: the row shows "Reading the sync folder…" (with the plural form while files download) and Cancel.
3. No rows: the row shows "Through <folder>", with the existing buttons; if a fast-forward waits the button is Restart. No question, no sheet (equal values, an empty folder and a fresh install are never asked).
4. Rows: the sheet opens as the continuation of the click if the Settings window is on screen, otherwise "Choose which settings this Mac uses" with Choose Settings…. Cancel in the sheet writes nothing.

### 4. Settings → Advanced layout

Layout stays: `HolzBarSection("Settings")` holds the backup row then the sync row; the sync row is `LabeledContent` with the button `HStack` on the trailing side and a label `VStack(alignment: .leading, spacing: 2)` carrying the title and the status lines, then the annotation. No new section, no disclosure group, no table in the pane. The backup row's annotation ("Exports layout, hotkeys and appearance to a file that can be imported on another Mac.") is unchanged.

### 5. Profiles in the Menu Bar Layout pane

Only the footnote and the delete-confirmation sentence above. The profile list shows the profiles the Mac can apply: on macOS 27 all synced profiles; on macOS 26 only profiles that have a macOS 26 layout (a profile created on macOS 27 is not listed there, because applying it would do nothing). A profile applied by a Space or display binding and a profile saved on macOS 26 stay silent: no sheet row, no status line.

### 6. Accessibility, localization, appearance

- VoiceOver: each sheet row is one combined element reading "<setting>, this Mac: <value>, sync folder: <value>, changed on <date>"; pop-ups are labeled "Value to use for <setting>"; the clash row reads its sentence with "this Mac" and "another Mac" spelled out; dimmed rows read "Already decided on another Mac". Status lines are plain `Text` in the sync row's label, so they are read with the row; the hint button keeps its visible title as label.
- Every string has de, fr, it and rm. German runs about 40% longer than English: no fixed widths on text except the three sheet columns above, which truncate with `.help`; status lines wrap.
- Dates and numbers through `FormatStyle`, never string building; the date is the minting Mac's, shown only.
- Light and dark mode, increased contrast and reduced transparency follow the system; no animations are added (so Reduce Motion needs no special case).
- No new permission, no network, no log of other Macs' names or values.

## Assumptions (recorded because the maintainer delegated UI decisions)

1. The conflict sheet stays an `NSAlert` sheet with an `NSHostingView` accessory, not a custom SwiftUI `.sheet`, so the existing destructive flags, no-default rule, Escape handling and no-nested-run-loop behavior carry over unchanged.
2. A sheet opens directly only as the continuation of a join the user just started (existing behavior); every other question is a hint first (analysis §4.7 literal reading of `modal-alerts-1`).
3. Orange is used for exactly two status lines (folder not found, unreadable file); everything else is secondary text. Informational notes (newer or older holzBar, oversize icon, waiting files, unusable value) are never orange.
4. The bystander sheet needs its own buttons (Use Chosen Settings, Later), body text and "Not set" rendering, because "Keep This Mac's Settings" has no meaning when this Mac has no value (analysis lets a user answer from any Mac but gives no wording).
5. Rows with three or more values and bystander rows write the pop-up choice whichever bulk button is pressed; the buttons are enabled only after every such row has a choice (analysis §4.6.9, no clock-based pick).
6. On macOS 26 the profile list hides profiles that have no macOS 26 layout. Context D-05 leaves open whether such profiles are listed; hiding avoids an Apply button that does nothing. Planner: confirm against `LayoutProfiles` when implementing; if profiles with only a macOS 27 part stay listed, add the line "This profile has no macOS 26 layout." (new string, 5 languages) under the name and disable Apply.
7. The profile delete confirmation gains one sentence only when sync is on and the Mac runs macOS 27, because the delete syncs to the other macOS 27 Macs.
8. The macOS 26 pane copy never promises the arrangement syncs; it says the macOS 27 layout syncs between macOS 27 Macs and the macOS 26 layout stays local (D-04, D-05).
9. Strings removed by this phase: the paused note, the old `informativeText` of the question, and the old sync annotation. Each new string above needs de (Swiss spelling), fr, it and rm before CI; the planner owns the final key list and the plural variations.
10. Date format: abbreviated day and month plus hour and minute through `Date.FormatStyle`, year added only outside the current year; localized by the system, never hand-formatted.
