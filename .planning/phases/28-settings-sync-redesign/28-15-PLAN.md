## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sync folder → host | Anyone with write access to the folder can place files, links and folders in `holzBar/` and `Macs/` |
| host → user preferences and the folder | The host executes `applyUnits` and `writeOwnFile`; a mistake here writes user data or the wrong file |
| main thread → file system | A stalled provider must never block the menu bar |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-36 | Tampering | SyncFolderReader and Writer | high | mitigate | No symbolic links (`lstat`, `O_NOFOLLOW`), real folders only, size limits before parsing, strict names, at most 64 files, the writer refuses any destination but the own device file name; FolderAccessTests cover a link, a folder, an oversize and a damaged file |
| T-28-37 | Denial of service | Main-thread file access | high | mitigate | All folder access on one serial file queue with deadlines, the launch bounded to one second, dataless files never read; the lint rule fails any file-system or coordination call in a main-actor sync file |
| T-28-38 | Tampering | The legacy file | high | mitigate | The host reads it only through `SyncLegacyInput` metadata and founding, and no code path writes, replaces or deletes `Settings.plist` or `SettingsSyncLastSynced`; the tracer test asserts both are byte-identical after a full exchange |
