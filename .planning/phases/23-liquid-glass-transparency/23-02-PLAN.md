<objective>
Make holzBar's System Glass tint and the holzBar Shelf follow the system's Reduce Transparency and Increase Contrast options live (M27-03), using public API only.

Purpose: The two options ask apps to stop using semi-transparent backgrounds and to draw bolder edges (AppKit's header: UI backgrounds "should not be semi-transparent; they should be opaque"; high contrast means "a less subtle color palette or bolder lines"). holzBar draws its own glass tint and Shelf, so it has to do this itself (outline decisions: Reduce Transparency and Increase Contrast only, no slider without a public signal, no new switch).
Output: a pure `TransparencyTreatment` with tests, a small `TransparencyObserver`, the Shelf and the System Glass overlay following it, the hint in the appearance pane in five languages, and `Scripts/typecheck-app.sh`.
</objective>

## Interfaces

Contracts this plan defines (all in the app module; the first two also compile in the `HolzBarCore` test package):
- `nonisolated struct TransparencyOptions: Equatable, Sendable` (Core): `var reduceTransparency = false`, `var increaseContrast = false`, `var prefersOpaque: Bool` (either one).
- `nonisolated struct TransparencyTreatment: Equatable, Sendable` (Core): nested `enum Fill { asDesigned, opaque }` and `enum Border { asConfigured, visible }`; `var fill`, `var border`, `var borderOpacity: Double`; `static let visibleBorderWidth = 1.0`; `static let unchanged`; `static func menuBar(isGlass: Bool, options: TransparencyOptions, hasConfiguredBorder: Bool) -> TransparencyTreatment`; `static func shelf(options: TransparencyOptions, hasConfiguredBorder: Bool) -> TransparencyTreatment`.
- `extension TransparencyOptions { static var system: TransparencyOptions }` (app): reads `NSWorkspace.shared.accessibilityDisplayShouldReduceTransparency` and `accessibilityDisplayShouldIncreaseContrast`.
- `@MainActor @Observable final class TransparencyObserver` (app): `private(set) var options: TransparencyOptions`, `func start()` (idempotent: reads the options, then follows the change notification), `func stop()`.

There is deliberately no slider-level input: no public signal for the Liquid Glass slider is known (outline question 32, option A, and the planning-time SDK scan in plan 23-01), and an unused parameter would be dead code. If 23-01 decides `M27-04: follow`, a slider plan extends `TransparencyTreatment`; this plan does not wait for that. "System Glass" in this plan means the `MenuBarTintKind.systemGlass` tint, the only tint that is glass; the translucent solid, gradient and Follow Wallpaper tints are the user's own colours and stay as they are.

Decision table of `TransparencyTreatment` (what Task 1 builds and tests):
1. Neither option on: `.unchanged` (fill asDesigned, border asConfigured, opacity 0), for both surfaces and whatever the border setting.
2. Menu bar with a tint that is not System Glass (`isGlass == false`): `.unchanged`, whatever the options.
3. Either option on, System Glass or Shelf: fill `.opaque`. Border: `.visible` when the user has no border configured, with `borderOpacity` 0.9 when Increase Contrast is on (a bolder line) and 0.6 when only Reduce Transparency is on; when the user has a border configured: `.asConfigured` with opacity 0 (their line stays, a second one would double it).
