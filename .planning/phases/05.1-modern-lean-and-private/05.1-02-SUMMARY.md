# Phase 05.1 Plan 02: Least privilege and launch Summary

**holzBar now asks only for Accessibility at first launch and asks for Screen Recording from the Shelf, search, Layout pane or a menu bar shape with the reason; Ice settings of any version are migrated once while imported instead of an 11-step chain at every launch; swizzling and preview/app-group leftovers are gone; every build is hardened and CI checks it; settings sync uses a file presenter instead of a 300 s timer.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The search colour captured before the grant**
- **Found during:** Task 1
- **Issue:** `MenuBarSearchModel.updateAverageColorInfo` captured the menu bar and wallpaper whenever the search panel opened, without the permission (not in the plan's list).
- **Fix:** Same early return as the other capture paths.
- **Commit:** `956f866`

**2. [Rule 2 - Missing critical] Unbounded polling after a declined request**
- **Found during:** Task 1
- **Issue:** Starting the 1 s check from the in-context request would poll forever when the user decides against it.
- **Fix:** A permission not asked at launch stops checking 300 s after the request and ends its waits.
- **Commit:** `956f866`

**3. [Rule 1 - Bug] The Shelf has no environment object**
- **Found during:** Task 1
- **Issue:** `HolzBarShelfContentView` holds the app state as an observed object, so a hint reading it from the environment would crash there.
- **Fix:** `ScreenRecordingHint` takes the app state as a parameter.
- **Commit:** `956f866`

**4. [Rule 1 - Bug] A search panel used before setup**
- **Found during:** Task 2
- **Issue:** The lazy search panel could be created before the menu bar manager's setup (a search hotkey right at launch) and then never be set up.
- **Fix:** The setup sets up a panel created before it.
- **Commit:** `2bfbbf1`

### Smaller adjustments
