## Escape hatches kept, and why

- `nonisolated(unsafe) static let systemWideElement` (AXHelpers): an `AXUIElement` is an immutable reference any thread may use, but the type is not marked `Sendable`.
- `@unchecked Sendable` `MenuBarItemImageCache.CaptureResult`: returned from the capture queue; `CGImage` is not marked `Sendable`, the images are immutable once captured.
- `@unchecked Sendable` XPC `Session.Storage`: `XPCSession` is not marked `Sendable`; every access goes through the session's lock.
- `@unchecked Sendable` `SettingsSyncPresenter`: file presenters are called on their own queue; its state never changes.
- `OSAllocatedUnfairLock(uncheckedState:)` with `withLockUnchecked` where the locked state holds Accessibility elements, running applications or AppKit monitor tokens (MenuBarItemProvider27 state, SourcePIDCache, EventMonitor tokens, XPC listener).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] SWIFT_VERSION 6.2 instead of 6.0**
- **Found during:** Task 3
- **Issue:** The coordinator asked for the highest value Xcode 26.6 accepts (latest-stable rule); the plan's verify greps for `SWIFT_VERSION = 6.0;`.
- **Fix:** `SWIFT_VERSION = 6.2;` in all four configurations; Xcode accepted it and passes `-swift-version 6` (seen in the compiler's arguments). The plan's literal `6.0` check does not match; everything else in the verify does.
- **Commit:** `efe7749`

**2. [Rule 1 - Bug] Status item removal and the termination release**
- **Found during:** Tasks 1 and 3
- **Issue:** `MainActor.assumeIsolated` in a willTerminate observer released the macOS 27 assertions; a Task-based observer would run too late at termination. The status item storage's deinit touched a non-Sendable `NSStatusItem`.
- **Fix:** `AppDelegate.applicationWillTerminate` calls `Concealer27.releaseAllForTermination()` synchronously; the storage (alive as long as holzBar) has no deinit.
- **Commits:** `ae176bc`, `f198b1d`

**3. [Rule 3 - Blocking] HIDEventManager line limit**
- **Found during:** Task 3
- **Issue:** After moving the click bridge and the per-backend hit tests, HIDEventManager still had 766 lines (limit 700).
- **Fix:** The generic hit tests (menu bar, application menu, notch, Shelf, icon) moved to `holzBar/Events/MenuBarHitTesting.swift`, an extension of the manager; 630 lines remain.
- **Commit:** `efe7749`

**4. [Rule 1 - Bug] Compiler issues of Swift 6.3.3**
- **Found during:** Task 3 CI
- **Issue:** A region-checker limitation and a Release optimizer crash (see CI fixes 5 and 7).
- **Fix:** Equivalent code without the triggering patterns; the build job prints crash backtraces now.
- **Commits:** `9d0fd36`, `0e9b2d8`, `dd67acf`

**5. [Rule 2 - Missing] Debouncer throttle with the latest value**
- **Found during:** Task 2
- **Issue:** Several pipelines used `throttle(latest: true)` (Shelf frame, control item frame, appearance configuration).
- **Fix:** `Debouncer.throttle(latest:)` with a test.
- **Commit:** `7c87e12`

**6. [Rule 2 - Missing] Equal values and observation**
- **Found during:** Task 2
- **Issue:** `@Observable` reports every assignment; Combine pipelines used `removeDuplicates`, and repeated assignments (permissions every second) would redraw views.
- **Fix:** `ObservationLoop.observe` deduplicates equatable values (tested); models assign only changed values where they did so through `removeDuplicates` (permission state, navigation flags, menu bar flags).
- **Commit:** `7c87e12`

### Smaller adjustments and behaviour notes

- TDD: there is no Swift compiler here, so the RED step could not be run locally; the new suites (ObservationLoop 6 tests, Debouncer 4, MenuBarBackendKind 4) were written with their implementation and pass in CI.
- Event posting (move and click) runs on the main actor instead of nonisolated code: its taps deliver callbacks on the main run loop, every wait is an `await`, and the window bounds it polls are still read in detached tasks. The tap disabling in a cancellation handler now hops to the main actor before resuming the continuation.
- Observers that used `receive(on: DispatchQueue.main)` now hop with a Task; synchronous Combine sinks that had to stay synchronous use `didSet` (settings, control item state, overlay flags) or an override (`HolzBarShelfPanel.setFrame` updates the origin when the size changes).
- The image cache's 0.5 s throttle (first value), the item list's 1 s debounce, the overlay's 0.05/0.1 s debounces, sync's 5 s debounce, the appearance manager's 0.1 s debounce and throttle keep their delays (documented at each use). AppState's 0.1 s throttles of the Settings visibility and the image capture are replaced by deduplication of the Bool.
- The Settings window's visibility comes from a KVO observer on the Settings window (`SettingsWindowModel`) instead of a window publisher; `AppNavigationState.settingsWindow` replaces `MenuBarManager`'s copy.
- `ItemClicker27` reads on-screen windows through `WindowInfo` without `.excludeDesktopElements`; desktop windows are in its baseline and do not count as opened menus.
- `MenuBarItem.getMenuBarItems` asks `MenuBarBackends.current`; callers outside the managers that branch on macOS 27 (Shelf, search and groups calling `ItemClicker27`) are unchanged.
- README: the rows "Swift language mode" (Swift 6, data-race safety checked by the compiler) and "State management" (`@Observable`, no Combine) state the truth; no 🔜 left in them.
